Retrieval configuration chooses the service and model used to turn documentation and search queries into numeric vectors for search. These questions check whether that configuration is accepted and which provider/model pair its helpers select. Models predict these frozen functions’ behavior from supplied code or rules; they do not search or read a documentation site. Acceptance checks local configuration rules; it does not prove a remote model exists or an API call will succeed.

These are the 48 development cases in `data/shoalrun-known-v1.json`. Development cases are used to check the evaluation’s prompts and runner settings; they do not train the models. Each question is listed with the exact input, choices where applicable, and expected outcome from the pinned function. “Accepted” means that function returns without throwing.

[Source at the recorded revision](https://github.com/shoalrun/shoalrun/blob/6f59004f4e9323ef1de171caa233e59a01fb982d/framework/src/retrieval-config.ts). See [methodology](doc:guide.methodology) for scope and [the evaluation report](doc:report.2026-10-30) for results. These cases make the evaluation reproducible. Reserve separate held-out cases when tuning prompts.

`noul` is a yes/no question: the endpoint returns a probability of “yes”, and this runner uses a 0.5 cutoff. `choice` selects one of four named options, with a probability for each option.
