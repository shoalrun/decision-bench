Decision Bench is a workbench for comparing decision models against known answers.

**The evaluation on this site tests predictions about source-code behavior. It does not test reading, searching, or answering questions about a documentation site.**

We froze copies of eight Shoalrun functions in the dataset files. Each case supplies concrete inputs and asks what the code accepts, selects, or returns. Executing those functions establishes the correct answers. Models receive the relevant code or written rules directly in their request; they do not browse the repository or documentation.

For example, a case can ask whether a configuration makes a validation function return normally or throw an error. The model predicts the result, and the runner compares that prediction with the recorded, replayable execution result.

The runner makes fixed requests and grades decisions by exact comparison. No agents or LLM judges participate in a run. Configure a compatible decision or chat-completions endpoint; OpenRouter is one provider example, not a requirement.

## Why Shoalrun

I wanted a decision-model benchmarking workbench that I could own, experiment with, and change as needed. This repo lives in the Shoalrun organization because I maintain Shoalrun and can use its code to create datasets with known answers. Shoalrun supplies the test data; the workbench is intended to support datasets from other projects too.

## Read the questions

The Questions navigation groups cases by the behavior they test. Development cases check the evaluation’s prompts and runner settings; test cases measure performance after those choices are fixed. Neither set trains the models. `noul` means a yes/no probability question; `choice` selects one of four options.
